# Definition of Done

Agreed by the team. We will review this at each retrospective and update it only by team agreement.

## A story is Done when

- [ ] Its acceptance criteria are met.
- [ ] The feature works in the shared application and has been demonstrated to the team or Product Owner.
- [ ] The change is merged into `main` after review by at least one teammate.
- [ ] Relevant automated tests pass, and the change does not break existing functionality.

## A sprint is Done when

- [ ] Stories presented as complete meet the Definition of Done above.
- [ ] Unfinished stories are returned to the product backlog and recorded transparently.

## Not required for every story

The following are addressed when relevant, rather than being required for every story: full
test coverage, deployment, performance testing, security hardening, architecture documentation,
and documentation that is unaffected by the change.
